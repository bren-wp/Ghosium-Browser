# Ghosium source-engine integration

This directory contains the Ghosium-owned product configuration, localization contract, brand assets and reviewed Windows build arguments used to transform the exact source revision pinned in `ENGINE_SOURCE_REVISION`.

The active development version is `0.1.12`. A source patch or audit is not a finished browser build; production status requires the controlled full-source Windows compile, runtime verification, canonical Setup/Portable round trip, signing and release evidence for the exact commit.

## Source lock

Production source is pinned by:

- `ENGINE_SOURCE_REVISION` — exact engine source commit;
- `DEPOT_TOOLS_REVISION` — exact compatible build-tool commit;
- `engine/build/windows-x64.args.gn` — reviewed Windows x64 build configuration.

The checkout must be detached at the exact source commit. Production builds must not use a floating branch, moving tag or unreviewed local source modifications.

## Ghosium-owned source changes

The transformation owns the Ghosium product layer, including:

- `Ghosium Browser` / `Ghosium` / `Brendigo` product identity;
- canonical `Ghosium-Browser.exe` and `Ghosium-Proxy.exe` Windows identities;
- product artwork and Windows icon resources;
- `ghost://` and `ghost-untrusted://` internal WebUI namespace;
- a native Ghosium New Tab with the canonical local product mark;
- removal of provider-owned New Tab Doodle/cloud/promo/AI entry points from the Ghosium-owned surface;
- Google Search as the explicit external default search service plus Ghosium Store, Support, Security, Terms, Privacy and update destinations;
- local-only profile/account surfaces where cloud services are not owned by Ghosium;
- native Ghosium product-version reporting;
- native same-product update integration;
- 38-language product branding/localization;
- privacy-strong native preference defaults;
- reviewed performance defaults.

Normal web navigation is never restricted to Ghosium-owned hosts. Host restrictions apply only to URLs generated by Ghosium-controlled product UI and update logic.

## Public branding boundary

Public Ghosium product surfaces must not expose legacy upstream browser product branding. This includes About, Settings, New Tab, installer UI, shortcuts, public executable metadata, Store/Update pages and first-party help links. External services such as Google Search remain externally owned and must never be falsely relabeled as Ghosium services; Ghosium-owned interface copy may stay provider-neutral.

Technical source-tree paths, asset filenames, symbol names and GN/Ninja targets can retain upstream implementation names when changing them would require a coordinated build-system/runtime migration. Those names are engineering dependencies, not public product identity. Where an upstream technical asset filename remains, byte-hash verification must prove the shipped/rendered asset is the reviewed Ghosium asset.

Required third-party copyright, license and attribution text is preserved only in the applicable legal/license material. It must not be rewritten as Brendigo ownership.

## Languages

Ghosium `0.1.12` defines **38 supported locales**:

```text
en-US, hr, de, fr, es, it, pt-PT, pt-BR, nl, pl,
cs, sk, sl, hu, ro, bg, el, tr, ru, uk,
sv, da, nb, fi, ja, ko, zh-CN, zh-TW, ar, he,
sr, ca, et, lv, lt, id, th, vi
```

English (`en-US`) is the primary/default locale. Croatian (`hr`) is mandatory and selectable in both browser and Setup. The Setup and browser locale sets are verified as one contract by CI.

Ghosium-specific localized strings are applied to every supported translation bundle. When a product-specific translation is not explicitly overridden, existing localized engine wording is rebranded without exposing legacy browser product names.

## Native New Tab integration

`scripts/harden-native-new-tab.ps1` operates on the exact pinned source revision before GN generation. `scripts/verify-native-new-tab.ps1` independently verifies the resulting source contract.

The 0.1.12 contract requires:

- the native New Tab static mark bytes to match `engine/branding/ghosium-mark.svg` exactly;
- the rendered logo layout to be Ghosium-owned rather than stock Google logo branding;
- no constructor-time remote Doodle fetch;
- OneGoogleBar disabled;
- animated Doodles and murals disabled;
- provider/Microsoft modules disabled;
- AI/Composebox/Threads entry points disabled;
- Lens and voice-search New Tab entry points disabled;
- action chips and browser promos disabled;
- NTP prefetch/prerender triggers disabled;
- local shortcuts, local customization and the normal omnibox/search flow preserved.

The source tree may retain an upstream technical asset filename such as `google_logo.svg`; that filename is not public branding, and verifier SHA-256 equality proves the actual bytes are the canonical Ghosium mark.

## Native privacy defaults

`scripts/harden-privacy-defaults.ps1` changes only reviewed native preference defaults on the exact pinned source. `scripts/verify-privacy-defaults.ps1` rejects anchor drift or weaker defaults.

New/default profiles require:

- third-party cookies blocked by default;
- search suggestions disabled by default;
- network prediction/speculative preloading disabled by default;
- remote alternate-error pages disabled by default;
- online spelling-service upload disabled by default.

These defaults do not remove the user's native settings/policy mechanisms and do not weaken Safe Browsing, TLS/certificate validation, sandboxing, site/process isolation, extension trust or update verification.

## Windows build configuration

`engine/build/windows-x64.args.gn` requires:

```text
is_debug = false
is_component_build = false
is_official_build = false
is_chrome_branded = false
target_cpu = "x64"
enable_background_mode = false
use_remoteexec = false
```

The build stays on the public/open-source configuration and does not inject proprietary third-party API credentials.

`enable_background_mode = false` prevents the legacy background-app mode from intentionally keeping Ghosium resident after the last browser window closes. This is a product lifecycle/performance choice and does not disable renderer isolation, the sandbox, TLS validation or extension/update trust.

## Memory and performance defaults

`scripts/rewrite-engine-performance-defaults.ps1` changes only the default state of the native Memory Saver mechanism for profiles that have not explicitly selected a state.

The current contract preserves native Memory Saver controls, medium aggressiveness, the existing discard-time threshold, native tab freezing, user-configured exceptions and explicit user preferences.

0.1.12 also removes unnecessary native New Tab remote/cloud initialization and speculative NTP prefetch/prerender. These are expected to reduce background work, but performance claims are valid only after a comparable benchmark of the compiled source-built `0.1.12` binary.

Renderer process caps and security-disabling flags are forbidden as RAM shortcuts.

## Windows executable and installer architecture

The end-user Windows identities are:

```text
Ghosium-Browser.exe
Ghosium-Proxy.exe
Ghosium-Browser-Setup.exe
Ghosium-Browser-Portable.exe
```

The source build still invokes internal technical build targets needed to produce the runtime graph. Canonical public Setup and Portable packages are assembled from the same verified source-built stage by the repository packaging scripts.

The same public Setup handles:

```text
install
/S /UPDATE
/S /UNINSTALL
```

Ghosium does not intentionally distribute a standalone updater or standalone uninstaller executable. Update and uninstall preserve the external browser profile unless an explicitly separate profile-deletion operation is requested by the relevant technical test path.

During canonical update/uninstall, Setup first requests a normal shutdown of the `Ghosium-Browser.exe` process tree. Forced termination exists only as a maintenance fallback.

## Native update contract

The browser-owned update flow uses:

```text
https://updates.ghosium.com/windows/stable.json
```

The updater must validate schema, product, platform, channel, newer version, exact trusted Setup URL, byte size, SHA-256, Authenticode status, publisher relationship and signed Ghosium product metadata before launching the same Setup package in update mode.

The checked-in manifest is disabled by default. Enabled production update metadata is generated only from the exact verified signed Setup artifact.

## Build sequence

From a controlled Windows builder:

```powershell
./scripts/verify-source-builder-host.ps1
./scripts/bootstrap-engine-source.ps1 -Destination C:\src\ghosium-engine -ReuseExisting
./scripts/apply-engine-branding.ps1 -SourceRoot C:\src\ghosium-engine\src
./scripts/verify-engine-fork.ps1 -SourceRoot C:\src\ghosium-engine\src
./scripts/verify-engine-windows-executable.ps1 -SourceRoot C:\src\ghosium-engine\src
./scripts/verify-engine-version-updater.ps1 -SourceRoot C:\src\ghosium-engine\src
./scripts/configure-engine-build.ps1 -SourceRoot C:\src\ghosium-engine\src -OutDir out/Ghosium
```

`configure-engine-build.ps1` applies and verifies the native New Tab, privacy-default, performance and legal transforms before `gn gen`.

Then run the pinned technical GN/Ninja targets required by the source graph:

```powershell
autoninja -C out/Ghosium chrome mini_installer
```

These target names are internal build API. They do not define public Ghosium product identity.

After compilation, use the repository verification/staging/packaging scripts rather than hand-copying binaries. The full-source workflow is the canonical production procedure.

## Security invariants

Source, branding, privacy, performance and packaging changes must preserve:

- browser, renderer and GPU sandboxing;
- site/process isolation;
- Safe Browsing;
- certificate/TLS validation;
- Windows exploit mitigations;
- extension permission/signature enforcement;
- update hash/signature/publisher verification;
- memory-safety and control-flow protections provided by the toolchain.

No performance or privacy result justifies disabling one of these boundaries.

## Store and search

`store.ghosium.com` is the first-party Ghosium extension-store surface. Package trust must remain fail-closed with explicit permission review, package integrity validation, signing/key trust, revocation and rollback-safe update behavior.

Google Search is the default external web search service. Ghosium-owned New Tab text is provider-neutral, while the source transform keeps Chromium's reviewed Google fallback and does not inject a Ghosium-owned search provider. User, policy and extension search overrides retain native precedence.

## Release gate

A production candidate must provide all of the following for the exact commit:

1. source-builder preflight;
2. pinned source/tool verification;
3. complete source transform and source audits;
4. native Ghosium New Tab transform verification;
5. native privacy-default verification;
6. deterministic Windows x64 configuration;
7. successful browser/runtime compilation;
8. compiled-output verification;
9. sandbox-preserving runtime smoke;
10. measured performance evidence;
11. canonical Setup + Portable build;
12. install → update → runtime → uninstall round trip;
13. locale/profile preservation checks;
14. production signing on `main`;
15. update manifest provenance;
16. SHA-256 evidence;
17. immutable release publication.

Until that controlled compile and runtime chain succeeds, `0.1.12` remains a source-development milestone rather than a proven source-built release.
